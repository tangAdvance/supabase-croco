## 数据流详解

### 1. 信息收集阶段

```
用户消息 → Edge Function → N8N
  ↓
意图识别 → 图片生成模式
  ↓
分析对话历史 (Message.metadata)
  ↓
判断收集进度:
  - 无 theme → 引导收集主题
  - 有 theme, 无 style → 展示风格选项
  - 有 theme + style, 无 emotion → 展示情感选项
  - 全部收集完 → 展示汇总并请求确认
  ↓
返回引导消息 → Edge Function → 客户端
```

### 2. 确认与生成阶段

```
用户确认 → Edge Function → N8N
  ↓
图片生成模式检测到确认
  ↓
构建完整 Image_Prompt:
  theme + style_suffix + emotion_suffix + character_personality
  ↓
设置 trigger_generation = true
  ↓
立即返回"生成中"响应 → Edge Function → 客户端
  ↓
客户端显示"AI 正在创作中..."
```

### 3. 异步生成阶段

```
N8N 异步分支:
  ↓
检查 trigger_generation = true
  ↓
准备图片生成数据
  ↓
调用 DALL-E 3 API (10-20秒)
  ↓
处理 API 响应:
  - 成功 → 提取 image_url 和 metadata
  - 失败 → 错误处理 + 重试 (最多 2 次)
  ↓
(待实现) 存储到 user_generated_images 表
  ↓
Supabase Realtime 自动推送
  ↓
客户端收到通知 → 显示图片
```

## 关键设计决策

### 1. 对话历史作为状态

**优点**:
- 无需额外的状态管理表
- 利用现有的 Message.metadata 字段
- 状态自然持久化
- 支持用户修改和重新确认

**实现**:
```javascript
// 从对话历史中提取 CreationContext
function extractCreationContext(history) {
  const context = {
    theme: null,
    style: null,
    emotion: null
  };
  
  // 从最近的消息中提取
  for (const msg of history.slice(-10).reverse()) {
    if (msg.metadata?.image_theme && !context.theme) {
      context.theme = msg.metadata.image_theme;
    }
    if (msg.metadata?.image_style && !context.style) {
      context.style = msg.metadata.image_style;
    }
    if (msg.metadata?.image_emotion && !context.emotion) {
      context.emotion = msg.metadata.image_emotion;
    }
  }
  
  return context;
}
```

### 2. 异步生成不阻塞对话

**优点**:
- 用户体验流畅，不需要等待
- 可以在生成期间继续对话
- 图片生成失败不影响对话流程

**实现**:
```
响应格式化
  ├─→ 返回响应 (主分支，立即返回)
  └─→ 检查是否触发图片生成 (异步分支)
       └─→ 图片生成流程 (后台执行)
```

### 3. 错误处理与重试

**策略**:
- 最多重试 2 次
- 每次重试前等待 2 秒
- 记录详细错误日志
- 不阻塞主流程

**实现**:
```javascript
if (retryCount < maxRetries) {
  // 重试
  return { shouldRetry: true, retryCount: retryCount + 1 };
} else {
  // 最终失败
  return { shouldRetry: false, finalError: true };
}
```

### 4. Realtime 通知

**优点**:
- 自动推送，无需轮询
- 减少服务器负载
- 实时性好

**实现**:
```sql
-- 启用 Realtime
ALTER PUBLICATION supabase_realtime ADD TABLE user_generated_images;
```

```dart
// 客户端订阅
supabase
  .channel('image-generation')
  .onPostgresChanges(
    event: PostgresChangeEvent.insert,
    schema: 'public',
    table: 'user_generated_images',
    filter: PostgresChangeFilter(
      type: PostgresChangeFilterType.eq,
      column: 'user_id',
      value: currentUserId,
    ),
    callback: _handleNewImage,
  )
  .subscribe();
```

## 性能考虑

### 响应时间

- **主流程响应**: < 5 秒（立即返回"生成中"）
- **图片生成**: 10-20 秒（异步执行）
- **Realtime 推送**: < 1 秒（图片生成完成后）

### 并发处理

- 每个用户的请求独立处理
- 使用 userId 和 conversationId 隔离数据
- N8N 支持并发执行

### 错误恢复

- API 调用失败自动重试
- 重试失败记录日志
- 不影响用户对话体验

## 安全考虑

### 数据隔离

- RLS 策略确保用户只能访问自己的图片
- API 调用使用 Service Role Key
- 图片 URL 可以使用签名 URL

### 内容审核

- 在调用 API 前检查 prompt 内容
- 使用 OpenAI 的内容过滤
- 记录所有生成请求

### 配额控制

- 限制每个用户每天的生成次数
- 监控 API 使用量
- 设置成本告警

## 扩展性

### 支持多种图片生成 API

当前实现使用 DALL-E 3，可以轻松扩展支持：
- Midjourney
- Stable Diffusion
- 其他图片生成服务

只需修改"调用 DALL-E 3 API"节点的配置。

### 支持更多风格和情感

在 `STYLE_PRESETS` 和 `EMOTION_PRESETS` 中添加新的预设即可。

### 支持角色个性化

在 `characters` 表中添加 `image_generation_config` 字段，存储角色的图片生成偏好。

## 监控与日志

### 关键指标

- 图片生成成功率
- 平均生成时间
- API 调用失败率
- 用户生成频率

### 日志记录

- 所有 API 调用（成功/失败）
- 错误详情和重试次数
- 用户生成请求
- 性能指标

## 总结

该架构设计实现了：
- ✅ 对话式引导体验
- ✅ 异步生成不阻塞
- ✅ 完善的错误处理
- ✅ 实时通知推送
- ✅ 数据安全隔离
- ✅ 良好的扩展性

核心优势：
1. **用户体验优先**: 立即响应，不需要等待
2. **架构简洁**: 利用现有系统，无需额外状态管理
3. **容错性强**: 完善的错误处理和重试机制
4. **易于扩展**: 支持多种 API 和风格配置
