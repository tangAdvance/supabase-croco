### 2. 提示词管理系统

#### 文件结构
```
.kiro/prompts/
├── README.md                  # ✅ 使用说明
├── registry.json              # ✅ 提示词索引
├── chat/                      # ✅ 对话模态
│   ├── beginner.md            # ✅ 启蒙期（6-9岁）
│   ├── explorer.md            # ✅ 探索期（10-12岁）
│   └── advanced.md            # ✅ 深化期（13-15岁）
└── podcast/                   # 🚧 播客模态
    └── beginner.md            # ✅ 启蒙期（示例）
```

#### 提示词特点

**启蒙期（6-9岁）**：
- 简单易懂，短句为主
- 多用比喻、拟人、童话故事
- 每次回复 100-200 字
- 语气亲切、充满童趣

**探索期（10-12岁）**：
- 逻辑清晰，有因果关系
- 引导思考，提出问题
- 每次回复 200-400 字
- 鼓励探索和尝试

**深化期（13-15岁）**：
- 深度分析，跨学科关联
- 批判性思考，多角度
- 每次回复 300-600 字
- 引导独立思考和判断

## 🔄 使用流程

### 开发者视角

1. **添加新模态**：
   - 在 `.kiro/prompts/` 下创建新文件夹
   - 创建三个年龄阶段的提示词文件
   - 在 `registry.json` 中注册
   - 更新代码以支持新模态

2. **修改现有提示词**：
   - 编辑对应的 `.md` 文件
   - 更新版本号和日期
   - 测试并部署

3. **查看提示词**：
   - 查看 `registry.json` 了解所有提示词
   - 阅读 `.kiro/prompts/README.md` 了解使用方法

### AI Agent 视角

当我（AI Agent）需要生成内容时：

1. 获取用户年龄
2. 计算年龄阶段（beginner/explorer/advanced）
3. 根据模态（chat/podcast/image等）和阶段加载提示词
4. 注入用户信息、角色信息、记忆等动态参数
5. 使用构建好的提示词生成内容

## 📝 示例对比

### 解释"引力"概念

**启蒙期（6-9岁）**：
> "因为地球妈妈特别喜欢拥抱呀！她像一块超级大的隐形磁铁，不管你跳多高，她都想把你拉回怀里抱抱。"

**探索期（10-12岁）**：
> "这和质量有关。任何有质量的物体都有引力。就像你在蹦床上放一个保龄球，床面会凹陷下去，旁边的玻璃珠就会滚向它。"

**深化期（13-15岁）**：
> "根据爱因斯坦的广义相对论，质量会使周围的时空发生弯曲。这个弯曲就是我们感受到的引力。这个理论预言了黑洞、引力波等现象，都已被观测证实。"

## 💡 设计亮点

### 1. 文件化管理
- 提示词存储在 Markdown 文件中
- 易于阅读和编辑
- 支持版本控制（Git）
- 可以直接在 IDE 中查看和修改

### 2. 动态参数系统
- 支持 `{{paramName}}` 语法
- 自动替换用户信息、角色信息、记忆
- 支持自定义参数
- 安全性验证

### 3. 模块化设计
- 年龄阶段计算器独立
- 提示词加载器独立
- 提示词构建器独立
- 易于测试和维护

### 4. 缓存机制
- 提示词加载后缓存
- 减少文件读取次数
- 提高性能

### 5. 扩展性
- 易于添加新模态
- 易于添加新年龄阶段
- 预留多语言支持接口

## ⚠️ 注意事项

### 1. 提示词更新
- 修改提示词后需要重新部署 Edge Function
- N8N 环境变量需要手动更新
- 建议使用版本号追踪变更

### 2. 参数安全
- 所有动态参数都经过安全验证
- 防止注入攻击
- 限制参数长度

### 3. 内容安全
- 所有提示词包含内容安全指令
- 不生成不当内容
- 对敏感话题有特殊处理

### 4. 性能考虑
- 使用缓存减少文件读取
- 预加载常用提示词
- 异步加载非关键提示词
